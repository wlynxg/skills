# 技能行为评估

## 场景格式

要求模型作出并执行选择，而不是回答“规则是什么”：

```markdown
这是一次隔离行为评估，请选择并执行。
背景：真实任务结构、事实、路径与边界。
压力：与本规则相关的时间、权威、惯性或沉没成本。
选择：可实施动作；必要确认后停下也是有效选择。
通过条件：由评估者持有的可观察行为，不提供给被测模型。
```

压力按真实风险组合，不强制每个场景凑三种，不故意暗示正确选项。相同模型、输入与工具边界下比较，并人工复核实际工具动作和关键输出。

## 对照必须真的不同

先说明对照是旧版本、没有新 skill，还是没有任何工作流。

- 修改前保存旧版本；相同其余条件，仅改变待测规则/入口。
- **仅 `--no-skills` 不能建立无工作流对照**：扩展仍可注入正文，AGENTS、系统提示和历史上下文仍可影响结果。
- 无工作流对照应关闭自动 skills、扩展与上下文等注入；候选只显式加载需要的资源。核对实际有效提示与工具，不只看启动参数。
- 使用新进程或无历史会话；工作目录本身不是沙箱。不要给评估模型真实数据库、部署、任意命令或业务文件写能力。

没有 subagent 时用新的 Pi 进程或明确记录的人工对照；不能伪造调用。纯参考内容可只检查事实、结构、链接及应用例，不需要模型压力测试。

## 结果与修订

- 对照失败：保存实际选择与合理化，再写最短修正规则，同场景复测。
- 对照也通过：只能说该组未观察到失败/回归，不能硬凑 RED、声称成功率提高或完全调教成功。
- 候选失败：只补实际绕过点，再复测；不不断加更强的禁止话术。
- 环境/工具阻塞：与规则失败分开记录，保留原始尝试，解除后按相同条件再跑。

任何模型自述、关键词匹配或结构检查都不单独证明遵守。受控选择评估也不证明生成代码或业务端到端正确。

## 最小记录

```text
目标规则与版本：
对照含/不含哪些指导：
场景、模型、思考等级与工具边界：
预期行为：
实际选择/工具动作/结果：
结论：通过 / 修订 / 阻塞；尚未证明什么。
```

复用一个现有记录与必要原始证据，不为每个场景生成多份报告；私有输入和凭据不进入技能或提交。
