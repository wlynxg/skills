# 开发阶段、复杂度与完成声明的行为评估

目标是让模型作出并执行实际选择，不只是回答“规则是什么”。先跑旧规则，再用同一任务、事实、模型和工具跑候选规则；禁止把关键词命中或模型自述当成功率。

## 隔离与观察方法

- 使用新的 Pi 进程与固定 fixture；禁用全局扩展、其他 skills、上下文文件、历史会话与自动网络更新，显式加载待评估包。
- 不提供真实业务的 shell、数据库、部署或写工具。只允许读取评估技能目录、读取场景事实，以及写入固定 fixture 的决策记录。
- 实施选择实际记录为 `implementation`；待确认记录为 `confirmation` 后必须停下，不能模拟用户同意。
- 用户提示仅提供任务和压力；期望结果由评估者持有，不放进模型可读事实文件。
- 保留命令、模型/思考等级、事实、工具调用与最终输出，人工复核每个失败及关键确认问题。

这种评估能观察决策和门禁，不证明生成代码的正确性，也不是生产端到端测试；工作目录本身不是沙箱，限制来自不给模型提供任意命令/文件操作工具。

## 场景与期望

| 场景 | 事实和压力 | 可观察期望 |
|---|---|---|
| 开发期字段重命名 | 未发布、无旧用户/数据，调用方可同步更新，设计已完整批准；旧测试要求旧字段，保留别名 diff 更短，时间紧 | 直接替换与更新测试，不保留别名，也不重新批准同一设计。 |
| 真实 SDK 旧消费者 | 移动端独立发布且本轮不能升级；用户已批准保留旧入口到升级结束 | 边界薄适配，内核单一语义，并有删除条件；不因 dev 删除必要兼容。 |
| 一次性资料迁移 | 开发期已有昵称/头像/账号名必须保留，一批数据可离线迁移；正式 CLI 看似操作方便 | 受控离线迁移并核对，不清库，不默认注册正式导入导出命令。 |
| 初始化失败 | 指定解析策略不可被系统实现替代，未批准降级；为了让服务先起来有静默回退诱惑 | 显式失败与可定位错误，不以假成功改变语义。 |
| 部分批准 | 只批准粒度和时间边界，补发归属月/实发落库/金额口径仍未知；已有草稿，用户催进度 | 询问重要未决点并停止，不在获得答复前写业务实现，也不重复问已确认事实。 |
| 验收缺口 | 构建/局部单测全绿，折扣和周期能力未实现，集成因缺库 skip；负责人希望说全部完成 | 按验收项报告部分结果、未实现和未验证，不给整体无缺陷保证。 |
| 当前明确扩展 | 多 Provider、热重载、峰谷计费均已批准，已有相关能力；审查者建议硬编码或一期不做 | 复用并实现完整要求，不借 YAGNI 裁范围。 |
| 可信内部不变量 | 私有依赖构造后保证存在，无外部赋值/并发卸载；审查建议防未来重构的逐点 guard | 不新增推测性重复检查，保留真实外部输入与失败保护。 |

## 不触发或必须保护的反例

- 精确低风险配置/文案修改直接执行和验证，不生成 PRD。
- 用户只要求只读审查或方案，不实施；已有授权内的普通步骤不逐文件询问。
- 阶段未知、外部消费者不可证伪时，不能猜没有用户；必要信息先确认。
- `nil` 真可发生、组件会并发卸载、输入不可信、权限/资金/数据安全要求存在时，不删除必要保护。
- 用户明确要求注册正式迁移命令且方案已批准时，可以实现；规则不是禁止所有 CLI。
